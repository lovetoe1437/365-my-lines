# Эксплуатация и резервное копирование

Этот документ описывает безопасные операции для production-версии «365 моих строк». Все команды выполняются из корня проекта после авторизации Wrangler.

## Резервная копия D1

Перед миграциями, выпуском новой версии или ручным изменением данных выполнить:

```bash
npm run backup:d1
```

Команда:

- только читает удалённую базу `365-my-lines-db`;
- экспортирует схему и данные;
- создаёт файл с датой и временем в каталоге `backups`;
- завершает работу с ошибкой, если экспорт не удался или файл пустой.

Каталог `backups` игнорируется Git. Его содержимое может включать личные записи и не должно отправляться в репозиторий, облачное хранилище без шифрования или переписку.

После экспорта проверить, что команда завершилась без ошибки и сообщила ненулевой размер файла. Содержимое SQL-файла без необходимости не выводить в терминал.

## Проверка перед публикацией

1. Убедиться, что рабочее дерево Git содержит только ожидаемые изменения.
2. Создать резервную копию командой `npm run backup:d1`.
3. Выполнить `npm test`.
4. Выполнить `npm run build`.
5. Проверить ожидающие удалённые миграции:

```bash
npx wrangler d1 migrations list 365-my-lines-db --remote
```

6. Если есть проверенные миграции, применить их отдельно:

```bash
npx wrangler d1 migrations apply 365-my-lines-db --remote
```

7. Опубликовать уже проверенную сборку и выполнить короткую проверку production.

## Автоматическая проверка

GitHub Actions выполняет одинаковый контроль на каждом push в `main`, для pull request, вручную и раз в неделю:

- чистую установку зависимостей через `npm ci`;
- аудит production-зависимостей с порогом высокой важности;
- все автоматические тесты;
- production-сборку Astro для Cloudflare.

Workflow не получает production-секреты, не обращается к D1 и не выполняет публикацию. Ошибка проверки должна быть изучена до следующего выпуска; автоматическое исправление зависимостей не используется.

## Восстановление

Восстановление — отдельная потенциально разрушительная операция. Его нельзя запускать автоматически или одновременно с обычной публикацией.

Предпочтительный порядок:

1. прекратить запись новых данных;
2. определить точное время корректного состояния;
3. проверить доступную точку Cloudflare D1 Time Travel;
4. по возможности восстановить или импортировать данные сначала в отдельную тестовую базу;
5. проверить количество и содержимое записей книги, дневника и настройки Unspoken;
6. только после отдельного подтверждения восстанавливать production.

Доступность точки Time Travel проверяется командой:

```bash
npx wrangler d1 time-travel info 365-my-lines-db
```

Команду `time-travel restore` или импорт SQL в production нельзя выполнять без предварительной проверки, актуальной резервной копии и явного подтверждения точного момента восстановления.

## Секреты и авторская сессия

- `ADMIN_PASSWORD`, `.env`, `.dev.vars` и значения KV не сохраняются в Git.
- Резервная копия D1 не заменяет резервирование или проверку KV binding `SESSION`.
- После изменения bindings или секретов необходимо отдельно проверить авторский вход и завершение сессии.
