# Architecture Audit — baseline 2.1.5

Дата аудита: 23 июля 2026

## Итог

Версия 2.1.5 является стабильной рабочей базой. Дизайн зафиксирован и не требует переработки. Архитектура в целом организована правильно: страницы, API, доступ к D1, авторизация, редакторская логика, UI-компоненты и стили разделены по назначению.

Главный оставшийся технический долг сосредоточен не в структуре каталогов, а в нескольких слишком крупных страницах и в неполном использовании уже созданных layout/surface-компонентов.

## Проверено

- структура `src/pages`, `src/components`, `src/lib`, `src/styles`;
- маршруты книги, дневника, редакторов и API;
- размеры исходных файлов;
- использование Foundation-компонентов;
- повторяющаяся клиентская логика;
- документация и roadmap;
- версия package и changelog.

## Ключевые находки

### A-01. Две reading-страницы слишком велики — высокий приоритет

- `src/pages/lines/[id].astro` — 917 строк;
- `src/pages/pages/[id].astro` — 912 строк.

Внутри каждой одновременно находятся загрузка данных, HTML, клиентский JavaScript и большой scoped CSS. Это повышает риск регрессий и усложняет поддержку.

Безопасный порядок разбиения:

1. вынести панель действий/toolbar;
2. вынести навигацию «предыдущая / следующая»;
3. вынести диалог удаления и связанную клиентскую логику;
4. только после визуальной проверки решать вопрос о CSS.

### A-02. Редактор строки заметно отстаёт по структуре — высокий приоритет

`src/pages/lines/[id]/edit.astro` содержит сжатую разметку и клиентский скрипт в одной строке, тогда как редактор дневника уже организован аккуратнее и использует общие элементы.

Нужно привести редактор книги к тому же уровню:

- использовать `EditorMeta` и `EditorActions`;
- вынести повторяющуюся логику сессии, сохранения и удаления;
- форматировать файл без изменения дизайна;
- сохранить текущие маршруты и тексты интерфейса.

### A-03. Foundation-компоненты используются частично — средний приоритет

Фактически используются:

- `Eyebrow`;
- `Heading`;
- `Text`;
- `Paper`.

Пока не используются:

- `Quote`;
- `Container`;
- `Section`;
- `Stack`;
- `Cluster`;
- `Card`;
- `Divider`.

Это не является ошибкой. Компоненты нельзя внедрять ради самого внедрения. Их следует подключать только там, где они реально убирают дублирование без визуальных изменений.

### A-04. Повторяется логика редакторов — средний приоритет

Повторяются сценарии:

- обработка истёкшей сессии;
- сохранение и удаление;
- уведомления Toast/Dialog;
- очистка localStorage;
- переход после успешного действия.

После стабилизации редактора книги эту логику стоит вынести в общий модуль.

### A-05. Документация roadmap устарела — низкий приоритет

`docs/ROADMAP.md` всё ещё описывает ранние версии 1.x, хотя текущая версия проекта — 2.1.5. Roadmap нужно синхронизировать с фактическим состоянием до релиза 1.0 продукта.

### A-06. Тестовый build в среде аудита не завершён

Установка зависимостей превысила лимит времени среды, поэтому окончательный `astro build` необходимо подтверждать локально после каждого изменения. В архиве не обнаружено признаков повреждения структуры package-файлов.

- обновить changelog.

## Definition of Done — Architecture 100%

- reading-страницы не содержат монолитные toolbar/navigation/delete-блоки;
- редакторы используют общую логику там, где поведение совпадает;
- нет визуальных изменений;
- все маршруты книги и дневника работают;
- создание, редактирование и удаление проходят успешно;
- 404 остаётся контекстным;
- локальный `npm run build` проходит;
- документация соответствует фактической версии проекта.
