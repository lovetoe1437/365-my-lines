# Структура проекта «365 моих строк»

Этот файл объясняет простыми словами, где находится каждая важная часть проекта.

## Главные папки

### `src/pages`

Все страницы сайта. Путь файла почти всегда совпадает с адресом страницы.

- `src/pages/index.astro` — главная страница и обложка книги.
- `src/pages/book.astro` — отдельная страница книги.
- `src/pages/login.astro` — вход автора.
- `src/pages/write.astro` — общий переход к созданию записи.

### `src/pages/lines`

Раздел «365 строк».

- `src/pages/lines/index.astro` — оглавление всех строк.
- `src/pages/lines/[id].astro` — чтение одной строки. Это главная страница Reading Experience.
- `src/pages/lines/write.astro` — создание новой строки.
- `src/pages/lines/[id]/edit.astro` — редактирование существующей строки.

### `src/pages/diary` и `src/pages/pages`

Раздел дневника.

- `src/pages/diary/write.astro` — создание записи дневника.
- `src/pages/pages/[id].astro` — чтение записи дневника.
- `src/pages/pages/[id]/edit.astro` — редактирование записи дневника.

### `src/pages/api`

Серверные обработчики. Они сохраняют, изменяют и удаляют данные.

Менять их нужно осторожно, потому что ошибки здесь могут повлиять на базу данных.

## Компоненты и макеты

### `src/components`

Повторно используемые части интерфейса.

- `Navigation.astro` — верхняя навигация.
- `components/ui/Button.astro` — общая кнопка.

### `src/layouts/AppLayout.astro`

Общий каркас страниц: `<head>`, шрифты, стили, навигация и основной контейнер.

## Логика проекта

### `src/lib/db`

Работа с базой данных Cloudflare D1.

- `book-lines.ts` — строки книги.
- `pages.ts` — страницы дневника.

### `src/lib/auth`

Авторизация и сессии.

- `password.ts` — проверка пароля.
- `session.ts` — авторская сессия.

### `src/lib/ui`

Небольшие общие функции интерфейса.

- `date.ts` — форматирование дат.
- `navigation.ts` — состояние навигации.

### `src/lib/editor`

Общая клиентская логика редакторов.

- `createEditor.ts` — создание страниц книги и записей дневника;
- `initBookLineEditor.ts` — редактирование страниц книги;
- `initDiaryPageEditor.ts` — редактирование записей дневника;
- `editorRuntime.ts` — безопасные ответы API, черновики и завершение сессии;
- `messages.ts` — контекстные книжные подсказки.

### `src/lib/validation`

- `entries.ts` — общая серверная валидация заголовков, дат и конфликтов уникальности.

### `tests`

Изолированные автоматические проверки критической логики. Они не обращаются к рабочей базе данных.

## Стили

### `src/styles/variables.css`

Цвета, шрифты, размеры, тени и дизайн-токены. Лучше сначала менять значение здесь, если оно используется во многих местах.

### `src/styles/global.css`

Общие стили всего проекта.

### `src/styles/components.css`

Общие стили кнопок и повторяющихся элементов.

### `src/styles/reading.css`

Стили старой/общей системы чтения. Современная страница строки также содержит локальные стили внутри `src/pages/lines/[id].astro`.

## Важные технические файлы

- `src/middleware.ts` — защита приватных маршрутов и проверка сессии.
- `src/content.config.ts` — конфигурация Astro Content.
- `wrangler.jsonc` — Cloudflare, D1, KV и bindings.
- `.dev.vars` — локальные секреты. Никогда не публиковать и не отправлять в GitHub.

## Что можно менять спокойно

- тексты и разметку страниц;
- локальные стили страниц;
- цвета и отступы в `variables.css`;
- документы в `docs`;
- визуальные компоненты.

## Где нужна осторожность

- `src/pages/api`;
- `src/lib/db`;
- `src/lib/auth`;
- `src/middleware.ts`;
- `wrangler.jsonc`;
- миграции базы данных.

## Основные команды

```bash
npm run dev
```

Запуск проекта локально.

```bash
npm run build
```

Проверка production-сборки.

```bash
npm test
```

Проверка критической логики редакторов.

Перед публикацией необходимо выполнить `npm test`, а затем `npm run build`.
